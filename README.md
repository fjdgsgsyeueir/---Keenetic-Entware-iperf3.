# iperf3_graph.sh

Мониторинг скорости интернет-соединения на Keenetic / Entware с использованием `iperf3`.

Скрипт автоматически проверяет скорость соединения с сервером, перебирает доступные порты, сохраняет результаты измерений, ведёт дневную и месячную статистику и отправляет уведомления о критически низкой скорости в MAX.

## Возможности

- **Измерение скорости:** тестирование через `iperf3` в режиме Reverse (`-R`).
- **Перебор портов:** последовательная проверка портов `5201–5209`.
- **Параллельные потоки:** используются 4 потока (`-P 4`).
- **Повторные попытки:** до 3 попыток при неудачном тестировании.
- **Защита от зависания:** принудительное завершение процесса, если тест не завершился за 40 секунд.
- **Защита от параллельного запуска:** PID-файл блокировки.
- **Дневная статистика:** количество измерений, средняя, минимальная и максимальная скорость.
- **Месячная статистика:** накопление измерений за текущий месяц.
- **Уведомления MAX:** предупреждения о низкой скорости, ошибках тестирования и ежемесячные сводки.
- **Email:** отправка полного месячного отчёта с историей измерений.
- **Автоматическая ротация:** при смене дня и месяца статистика предыдущего периода обрабатывается автоматически.

Скрипт рассчитан на Entware и использует следующие программы:

| Программа | Путь |
|---|---|
| Shell | `/opt/bin/sh` |
| iperf3 | `/opt/bin/iperf3` |
| curl | `/opt/bin/curl` |

Также используются `grep`, `head`, `tr`, `ps`, `kill`, `sleep`, `date` и `mkdir`.

Проверь наличие основных зависимостей:


## Конфигурация

Основные параметры находятся в начале скрипта.

### Параметры тестирования

```sh
LOG_DIR="/opt/var/log"
TMP_DIR="/opt/tmp"
IPERF_BIN="/opt/bin/iperf3"
SERVER="st.cheb.ertelecom.ru"

IPERF_PORT_START=5201
IPERF_PORT_END=5209
```

| Параметр | Назначение |
|---|---|
| `SERVER` | Сервер для проверки скорости |
| `IPERF_PORT_START` | Первый проверяемый порт |
| `IPERF_PORT_END` | Последний проверяемый порт |
| `IPERF_BIN` | Путь к исполняемому файлу iperf3 |
| `LOG_DIR` | Каталог журналов и статистики |
| `TMP_DIR` | Каталог временных файлов |

Порты проверяются строго по порядку. После первого успешного теста перебор прекращается.

### Порог критической скорости

```sh
CRIT_THRESHOLD_MBPS="90.0"
```

Если измеренная скорость оказывается ниже 90 Mbps, скрипт отправляет уведомление в MAX.

Порог можно изменить, например:

```sh
CRIT_THRESHOLD_MBPS="70.0"
```

### Настройки MAX и Email

Скрипт загружает дополнительные параметры из:

```sh
/opt/etc/proxy_monitor.conf
```

Для MAX используются:

```sh
MAX_CHAT_ID="..."
MAX_API_TOKEN="..."
```

Для электронной почты используются параметры SMTP:

```sh
SMTP_SERVER="smtps://smtp.example.com:465"
SMTP_USER="..."
SMTP_PASS="..."
MAIL_FROM="..."
MAIL_TO="..."
```

Указанные значения являются примерами. Используй реальные параметры своего почтового сервера.

Если `SMTP_SERVER` установлен в `smtp://`, отправка Email отключается.

**Важно:** файл конфигурации содержит токен MAX и пароль почты. Не публикуй его и ограничь доступ к нему.

## Как выполняется тестирование

1. Скрипт проверяет наличие предыдущего процесса и блокировки.
2. Проверяет, не наступил ли новый день или месяц.
3. Запускает `iperf3` для первого порта.
4. Если тест не удался, переходит к следующему порту.
5. После успешного теста получает скорость из JSON-результата.
6. Переводит значение из bit/s в Mbps.
7. Записывает результат в дневную и месячную статистику.
8. Проверяет скорость относительно критического порога.
9. При необходимости отправляет уведомление в MAX.

Параметры запуска iperf3:

```sh
-c st.cheb.ertelecom.ru
-p PORT
-t 30
-P 4
-4
-R
-J
--connect-timeout 5000
```

Таким образом, измерение выполняется в течение 30 секунд, по IPv4, с четырьмя параллельными потоками и получением результата в JSON.

### Повторные попытки

Если ни один порт не дал успешного результата, запускаются повторные попытки:

| Попытка | Ожидание перед следующей |
|---|---:|
| 1 | 10 секунд |
| 2 | 20 секунд |
| 3 | Повтор отсутствует |

После трёх неудачных попыток скрипт отправляет предупреждение в MAX.

## Файлы статистики и журналов

Все основные файлы находятся в `/opt/var/log/`.

| Файл | Назначение |
|---|---|
| `iperf3.log` | Журнал работы скрипта |
| `iperf3_daily_values.txt` | Измерения за текущий день |
| `iperf3_daily_stats.json` | Дневная статистика |
| `iperf3_daily_reset.flag` | Дата последнего сброса дневной статистики |
| `iperf3_monthly_values.txt` | История измерений за текущий месяц |
| `iperf3_monthly_stats.json` | Месячная статистика |
| `iperf3_monthly_reset.flag` | Месяц последнего сброса статистики |

Временные файлы и вспомогательные данные находятся в `/opt/tmp/`:

| Файл | Назначение |
|---|---|
| `iperf_monitor.lock` | PID активного процесса |
| `iperf_last_mbps.txt` | Последняя измеренная скорость |
| `iperf_last_port.txt` | Порт последнего успешного теста |
| `iperf_*.json` | Временный JSON-результат теста |
| `iperf_*.err` | Временный журнал ошибок iperf3 |

### Формат дневных измерений

```text
13ч05м 95.42
13ч10м 102.18
13ч15м 87.36
```

### Формат месячных измерений

```text
16.11.2026 13:05 95.42
16.11.2026 13:10 102.18
16.11.2026 13:15 87.36
```

### Формат JSON-статистики

```json
{
  "count": 3,
  "sum_mbps": 284.96,
  "min_mbps": 87.36,
  "max_mbps": 102.18
}
```

Средняя скорость вычисляется как сумма всех измерений, разделённая на их количество.

## Цветовая классификация скорости

В отчётах используется следующая классификация:

| Индикатор | Скорость |
|---|---:|
| 🟢 | Выше 100 Mbps |
| 🟡 | От 50 до 100 Mbps включительно |
| 🔴 | Ниже 50 Mbps |

Критический порог уведомления MAX настраивается отдельно через `CRIT_THRESHOLD_MBPS`.

## Дневные и месячные отчёты

### Дневной отчёт

При обнаружении нового дня скрипт:
- обрабатывает статистику предыдущего дня;
- вычисляет среднюю, минимальную и максимальную скорость;
- формирует список измерений с цветовой классификацией;
- сбрасывает дневную статистику.

**Особенность текущей версии:** отправка дневного отчёта в MAX отключена комментарием в коде. Отчёт формируется и обрабатывается, но не отправляется.

### Месячный отчёт

При обнаружении нового месяца скрипт:
- рассчитывает статистику предыдущего месяца;
- отправляет краткий отчёт в MAX;
- формирует полный отчёт с историей измерений;
- отправляет полный отчёт на Email;
- начинает накопление статистики нового месяца.

## Запуск

Сделай скрипт исполняемым:

```sh
chmod +x /opt/recovery/iperf3_graph.sh
```

Запусти вручную:

```sh
/opt/recovery/iperf3_graph.sh
```

Посмотреть журнал:

```sh
tail -f /opt/var/log/iperf3.log
```

Посмотреть последнюю скорость:

```sh
cat /opt/tmp/iperf_last_mbps.txt
```

Посмотреть последний использованный порт:

```sh
cat /opt/tmp/iperf_last_port.txt
```

Посмотреть дневную статистику:

```sh
cat /opt/var/log/iperf3_daily_stats.json
```

Посмотреть месячную статистику:

```sh
cat /opt/var/log/iperf3_monthly_stats.json
```

## Автоматический запуск через Cron

Для периодического мониторинга можно добавить задание в Cron.

Например, запуск каждые 5 минут:

```cron
*/5 * * * * /opt/recovery/iperf3_graph.sh
```

Интервал можно изменить в соответствии с необходимой частотой измерений.

Не рекомендуется запускать тесты слишком часто: каждый успешный тест занимает примерно 30 секунд и создаёт дополнительную нагрузку на соединение и тестовый сервер.

## Уведомления MAX

Скрипт отправляет уведомления в MAX в следующих случаях:

| Событие | Уведомление |
|---|---|
| Скорость ниже критического порога | Да |
| Все попытки тестирования завершились ошибкой | Да |
| Наступил новый месяц | Да |
| Наступил новый день | Нет, отправка отключена |

Для отправки используется API:

```text
https://platform-api2.max.ru/messages
```

## Важные особенности

- Скрипт не создаёт PNG-графики и не строит визуальные диаграммы. Название `iperf3_graph.sh` относится к мониторингу и накоплению данных для последующего анализа.
- При отсутствии успешного теста статистика не обновляется.
- Дневная и месячная статистика сбрасываются автоматически при первом запуске после смены соответствующего периода.
- Если скрипт не запускался в момент смены месяца, отчёт будет обработан при следующем запуске.
- Дневная история хранится только за текущий день. Месячная история хранится только за текущий месяц.
- Последняя скорость и использованный порт сохраняются в `/opt/tmp/`.
- Блокировка предотвращает параллельный запуск экземпляров скрипта.

**Примечание по коду:** в текущей версии итоговый `exit 0` выполняется независимо от результата `run_iperf_with_retries`. Поэтому код завершения процесса не следует использовать как достоверный индикатор успешности теста. Для проверки результата используй журнал и файл последней скорости.

## Лицензия и назначение

Скрипт предназначен для личного мониторинга качества интернет-соединения на устройствах с Entware. Для работы необходим доступ к указанному серверу iperf3 и его тестовым портам.
